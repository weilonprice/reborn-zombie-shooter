# The infected roster

Twelve archetypes — eleven plus the boss — generated by script, not modelled.

```bash
blender --background --python build_enemies.py                    # all twelve
blender --background --python build_enemies.py -- Screamer Brute  # a subset
blender --background --python render_roster.py -- Screamer        # proof renders
python3 measure.py NormalZombie Screamer                          # against the baseline
```

Output lands in `Assets/_Project/Art/Characters/<Name>/`.

## One skeleton. This is not negotiable.

Every clip in the game — Chase, Attack, GetShot, Stagger, Death, and the four
ability clips — is authored **once**, against the normal zombie, and borrowed by
all twelve. Two facts force the roster to share a rig exactly:

- **Generic rigs bind curves by transform PATH.** A differently-named armature
  breaks every clip at once, which is why the armature in all twelve files is
  still called `NormalZombie_Rig`. That name is load-bearing.
- **`build_zombie.py`'s `frame()` keyframes LOCATION on every bone**, not just
  rotation. A skeleton with longer arms would be snapped back to the zombie's
  proportions the moment a clip played.

So: identical bones, identical rest pose, twelve different bodies. Anything
needing a genuinely different posture needs its own clips and does not belong
here. Size differences come from mesh volume and from the uniform scale Unity
applies per archetype (`AbilityAnimationSetup` scales by controller height / 2.1).

## Separation is by plan-view mass

The camera sits at offset `(0, 18, -10)` — **61 degrees down**, about 20.6m out,
making a character roughly eighty pixels tall. Height barely reads at that pitch.
What reads is what crosses the shoulders, sits on the back, or changes the skull.

| | reads as |
|---|---|
| Brute / Boss | a slab of shoulders, head sunk between them; the boss adds a bone crown |
| Bloater | a sphere with limbs |
| Armored | hard plates among a roster of soft bodies |
| Spitter | a gland riding high on the back |
| Screamer | a pale throat and teeth against a dark body |
| Crawler | no legs, low, dragging |
| Runner / Revenant | stripped down; ribs where the torso should be |
| Sapper / RangedZombie | something carried, on the back or in one overgrown arm |

Ten skull shapes are defined in `SKULLS` and spread across the twelve. The first
version of this roster gave all of them the same cranium and left colour doing
all the work.

## Colour

`SKIN_SCALE`, `CLOTH_SCALE` and `TRIM_SCALE` in `build_enemies.py` are the only
value knobs. **Measure, do not eyeball** — run `measure.py`, which masks by real
alpha and compares against the baseline zombie. Two rounds of adjusting this by
eye went in the wrong direction; see debt 12 in `ROADMAP.txt` for why, and for
the palette-UV bug that was causing the thing being adjusted.

Skin stays green-dominant and these bodies expose far more of it than the
baseline, which is mostly shirt.

## One material per character

`enemy_kit.export()` bakes every material into a sixteen-cell palette texture and
collapses the mesh to a single material. Skinned meshes do not batch and the GPU
Resident Drawer does not touch them, so each material is a draw call on every one
of up to sixty enemies.

The bake **removes** the smart-project UV layer rather than deselecting it.
`active_render` does not survive an FBX round trip — the importer marks the first
layer as the render one — and shipping both layers means sampling a sixteen-cell
palette with a full unwrap, which scatters the colours at random. Removing a UV
layer also invalidates the other layer pointers, so the survivor is re-fetched by
name afterwards.
