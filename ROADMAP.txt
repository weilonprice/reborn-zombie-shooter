KNOWN DEBT IN THE CURRENT BUILD
===============================================================================

1. ARENA SCENE IS GENERATED.
   ArenaBuilder overwrites Arena.unity wholesale. Retire the tool the moment
   hand-authoring starts in Phase 2, or it will silently destroy level design.

2. INPUT IS POLLED DIRECTLY.
   InputReader reads devices rather than action maps. Commercial release needs
   full rebinding. Migrate to Input Actions in Phase 3 with the settings menu.

3. HUD USES LEGACY uGUI TEXT.
   Chosen to avoid the TextMeshPro import prompt on first run.
   Migrate in the Phase 2 UI pass.

4. NO SAVE OR SETTINGS PERSISTENCE.
   Needed before Phase 4 meta progression. Expensive to retrofit.

5. NO ASSEMBLY DEFINITIONS.
   Everything compiles into Assembly-CSharp. Add asmdefs before iteration
   times start costing real minutes.

6. ZOMBIE STEERING IS O(n^2), NOW WITH A PER-FRAME SPHERECAST ON TOP.
   ZombieAI.Separation walks every other live zombie each frame
   (ZombieAI.cs:210). Barricade sensing then adds a SphereCastNonAlloc per
   zombie per frame (ZombieAI.cs:141). At 60 agents that is ~3,600 distance
   checks plus 60 casts every frame; fine today, and the first thing to break
   when waves get dense.
   NOTE: this entry was briefly overwritten by the barricade-pathing note and
   marked resolved. It was not resolved - it got worse. Phase 4 references it
   for the spatial hash, so keep it at number 6.
   Fix: spatial hash or grid buckets for separation, and cache the barricade
   cast to every few frames rather than every frame.

7. SCENE SINGLETONS FAIL SILENTLY - AND THE PATTERN HAS SPREAD.
   Reached through null-conditional calls, so one missing from the scene
   simply does nothing - no error, no warning. Now 27 call sites:
   ArmoryManager 10, SfxPlayer 9, CameraShake 4, ImpactEffects 2, TracerPool 1,
   HitStop 1. Every new system adopted the pattern instead of the pattern
   being fixed. Has already cost several debugging round trips.
   Fix: startup validation on each singleton, and extend the builder's
   Validate step to assert every singleton, clip and prefab landed.

8. EVERY NEW SCENE COMPONENT NEEDS A BUILDER RE-RUN.
   Adding a component in code does nothing until ArenaBuilder is run again.
   Easy to forget, and the symptom is silent (see item 7). Goes away when the
   builder is retired at Phase 2.

9. HIT TEST IS A RAY, NOT A SPHERECAST.
   Shots are correct now that the ray starts at the player's centre, but an
   enemy that closes inside that centre would still be missed. Cannot happen
   at current values - zombies stop at 1.6 units - but a fast archetype in
   Phase 1 could. Switch to SphereCast when that enemy exists.

10. VFX SIZES ARE TUNED TO ONE CAMERA DISTANCE.
   Sparks and shell casings are sized in world units for a camera 22.8 units
   out (~45 px per unit). Any change to camera height or FOV silently changes
   how readable they are. Revisit if the camera framing moves in Phase 2.

11. THE BUILDER WILL NOT UPDATE EXISTING WEAPON ASSETS.
   LoadOrCreateWeapon only creates what is missing, deliberately, so hand
   tuning survives a rebuild. The flip side is that changing a default in
   ArenaBuilder does nothing to assets that already exist - they have to be
   edited in the inspector or deleted and regenerated. Expect this every time
   a weapon default changes.

12. WEAPON MODS ARE HARDCODED BY SLOT INDEX.
   Weapon.cs branches on slotIndex == 0, isShotgun = slotIndex == 1, and
   slotIndex == 2 || slotIndex == 3. Reordering the loadout silently
   reassigns every mod to the wrong gun, and a fifth weapon means editing
   Weapon.cs. This directly undoes the point of moving weapons into
   ScriptableObjects one commit earlier.
   Fix: mods declare what they apply to, or WeaponDefinition carries tags
   (shotgun / precision / sidearm) the mods match against.

13. ARMORY PRICES ARE COMPILE-TIME CONSTANTS.
   ArmoryManager holds every cost as const int, so balancing the economy is a
   recompile rather than an edit. Painful once run structure is fixed and the
   economy actually needs tuning against it.
   Fix: move costs into a ScriptableObject alongside the weapon definitions.

   Zombies sense a blocking barricade ahead and claw it down on their attack
