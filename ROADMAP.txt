Task list only. Each phase ends at a gate - do not start the next phase
until the gate passes.

PHASE 0 - PROVE IT'S FUN WITH ZERO ART            Weeks 1-2
===============================================================================

[x] Tuning pass - DONE 2026-09-08. Movement, shooting, aiming, reloading all
    confirmed good in play. No adjustments needed.
[x] Enemies spawning and killable - DONE 2026-09-08. Zombies spawn, take
    damage, die, and recycle. Wave counter and score both advance.
[ ] Hit feedback - damage flash, knockback, hit-stop on kill.
    (Damage is currently invisible. Biggest remaining feel gap.)

[ ] Death moments - dissolve, ragdoll pop, or gib burst.
[ ] First audio - gunshot, impact, zombie death, low ambient bed.

GATE 0: A stranger keeps shooting for 30 seconds without being told to.


===============================================================================
PHASE 1 - FIND THE HOOK                           Weeks 3-8
===============================================================================

[ ] Move weapon stats into ScriptableObjects so weapons are data, not code.
[ ] Build 3-4 weapons that genuinely play differently (not stat variations).
[ ] Enemy archetypes - runner, brute, ranged/exploder. Each must force a
    different player response.
[ ] Between-wave choice - upgrade draft or shop. Source of build variety.
[ ] Define run structure - run length, win condition or endless + score.
[ ] Write the hook in one sentence: why pick this over the dozen alternatives.

GATE 1: You voluntarily play 5 runs back to back, and can state the hook in
one sentence a stranger finds interesting. Failing this means changing the
design, not adding polish.


===============================================================================
PHASE 2 - VERTICAL SLICE & ART DIRECTION LOCK     Weeks 9-16
===============================================================================

[ ] URP post-processing stack - bloom, color grading, vignette, subtle grain.
    Does more for a minimal look than any model would.
[ ] Lighting design - committed palette and mood, strong silhouettes,
    high contrast.
[ ] VFX language - consistent rules for muzzles, impacts, deaths, pickups.
[ ] Arena as level design - replace the generated box with a hand-authored
    space: cover, chokepoints, sightlines, a reason to move.
[ ] UI pass - migrate to TextMeshPro, design real HUD, main menu, pause.
[ ] Audio pass - full mix, music bed, dynamic intensity between waves.
[ ] RETIRE ArenaBuilder once hand-authoring starts (see debt item 1).

GATE 2: Capture 60 seconds of unedited play you would put on a store page
as-is. That clip becomes the Phase 3 trailer.

===============================================================================
PHASE 4 - CONTENT PRODUCTION                      Weeks 17-34
===============================================================================

Target counts are budgets, not minimums.

[ ] Enemy roster to ~12, including 2-3 bosses with real mechanics.
[ ] Weapons to ~10, each with a distinct role.
[ ] Upgrades to 60+, with intentional synergies.
[ ] Arenas - 3-4 hand-designed spaces with different tactical character.
[ ] Meta progression - unlocks and persistent goals that give a losing run

[ ] Performance - profile the horde. Expect the O(n^2) separation to need a

GATE 4: 10+ hours of play without repetition becoming obvious, and no run
feels like a strictly worse version of another.

===============================================================================
KNOWN DEBT IN THE CURRENT BUILD
===============================================================================

1. ARENA SCENE IS GENERATED.
   ArenaBuilder overwrites Arena.unity wholesale. Retire the tool the moment
   hand-authoring starts in Phase 2, or it will silently destroy level design.

2. INPUT IS POLLED DIRECTLY.
   InputReader reads devices rather than action maps. Commercial release needs
   full rebinding. Migrate to Input Actions in Phase 3 with the settings menu.

3. HUD USES LEGACY uGUI TEXT.
   Chosen to avoid the TextMeshPro import prompt on first run.
   Migrate in the Phase 2 UI pass.

4. NO SAVE OR SETTINGS PERSISTENCE.
   Needed before Phase 4 meta progression. Expensive to retrofit.

5. NO ASSEMBLY DEFINITIONS.
   Everything compiles into Assembly-CSharp. Add asmdefs before iteration
   times start costing real minutes.

6. ZOMBIE STEERING IS NAIVE.
   O(n^2) separation, fine for tens of agents, not hundreds. Revisit with
   Phase 4 performance work. NavMesh is installed if the map gains real
   obstacles.
