# Reborn

Top-down twin-stick zombie wave survival. Unity 6000.6.0f1, URP, new Input System.

Fifteen waves into a boss, then endless. Gold resets every run, so the build you
end with is the one you paid for that run and nothing carries over.

**In development.** Content is complete for Phase 2 and the art is in: a rigged
survivor, twelve infected archetypes, ten weapon models and a building set, all
authored as Blender scripts under [`ArtSource/`](ArtSource). The scene itself is
still generated by an editor script rather than hand-built, and the whole of it
is **barely play-tested** — see [ROADMAP.txt](ROADMAP.txt).

---

## Running it

The scene is **generated, not committed as authored content**. After a fresh
clone, or after changing anything the builder touches:

> **Tools → Zombie Shooter → Build Playable Arena**

That writes `Assets/_Project/Scenes/Arena.unity` from scratch — environment,
player, HUD, shop, prefabs, and every design asset that does not already exist.
It logs how many enemy archetypes it wired; if it reports a problem, re-run it
rather than fixing the scene by hand.

Then press Play.

Gamepad works for movement, aim and the first four weapon slots. Slots 5–10 are
keyboard only — see debt 18.

## What is in it

**Ten weapons**, each with one five-tier upgrade path. A maxed path costs 3,360
gold against roughly 6,580 of run income, so **a run can only ever max one**.
That choice — which weapon to pour gold into — is the run's identity.

**Twelve enemy archetypes** plus a boss, each attacking a different assumption
rather than varying a stat: walls are not safety, walls are the objective, close
range is dangerous, facing matters, one target matters more than the nearest, a
body is not finished, standing still is not free, a pack is not a stream.

**Fortification** — barricades, explosive barrels and claymores, placed on a
one-metre grid between waves and during them.

**Four arenas**, chosen at random per run — The Yard, The Corridors, The Ring,
The Warren — each changing what cover and barricades are worth rather than just
rearranging boxes.

[UPGRADES.txt](UPGRADES.txt) documents every authored path, tier by tier, along
with the economy it is priced against.

## Architecture worth knowing before changing anything

**`ArenaBuilder` owns the scene.** It runs in two passes — generate and flush
every asset, then build the scene loading them fresh off disk — because object
references do not survive `NewScene`. Adding a scene component means editing the
builder and re-running it, never editing the scene. It retires in Phase 3, which
is a one-way door.

**Content is data, not branches.** Weapons, deployables, upgrade trees, firing
modes and the wave roster are all ScriptableObjects or serialized tables. Adding
a weapon, an archetype or a tier should be an asset plus a line, with no new
field and no new branch. Where that rule was broken it cost a rewrite three
separate times — see debt 23.

**Two asset contracts, and they are opposites.** Weapon definitions are
overwritten from code on every build. Everything else — upgrade trees,
deliveries, deployables, prices — is create-if-missing and survives. So tune
weapons in `ArenaBuilder`, and tune trees in the inspector. Changing an authored
tier in code means deleting its asset first. See debt 11.

**Extension points, rather than flags on shared classes.** `WeaponDelivery` for
how a shot travels; `IDamageModifier`, `IDeathInterceptor`, `IEnemySteerOverride`
and `IEnemyMotionOverride` for what makes an archetype different. A new
behaviour should be a small component, not another boolean on `ZombieAI`.

**Bodies are shot through hit zones, not through their walking capsule.** A
CharacterController is sized for moving, and the authored infected reach their
arms well outside one: a quarter of a visible zombie used to be unhittable. Each
body carries a trigger capsule matching its silhouette, worth 0.6x damage, with
the walking capsule underneath at full damage — the delivery pays out the better
of the two, so centre mass is unchanged and a clipped arm now registers.
Hit zones are triggers, and every other physics query in the project passes
`QueryTriggerInteraction.Ignore`, so nothing else can see them.

**Characters share one skeleton and one material.** Every animation clip is
authored once against the normal zombie and borrowed by all twelve archetypes,
which only works because Generic rigs bind by transform path and the clips
keyframe bone location — so the bones, the rest pose and the armature name are
identical everywhere and must stay that way. Each character also bakes its
colours into a palette texture and ships a single material, because skinned
meshes do not batch: one material is one draw call per enemy, and sixty enemies
are alive at once.

**The horde shares one path.** `FlowField` sweeps a 90×90 grid outward from the
player and every enemy reads the cell it stands in — one array lookup each,
rather than sixty pathfinding queries. Barricades are stamped expensive rather
than impassable, so a short wall is a detour and a long one is a door.
